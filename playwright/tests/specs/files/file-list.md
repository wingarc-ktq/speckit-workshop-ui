# 文書一覧

## 注記

- 仕様書上の対象URLは `/files` と指定されていたが、実装上の文書一覧画面は `/`（マイファイル画面、`FilesPage`）である。本仕様書ではログイン後のホーム画面（`http://localhost:5173/`）を対象とする。
- `specs/002-document-management-example/spec.md` の User Story 2（文書一覧の表示）のうち、グリッドビューへの切り替えは現時点で未実装のため対象外とする。一覧はテーブル（リスト）表示のみで検証する。
- User Story 3（キーワード検索）のうち、検索一致部分のハイライト表示、およびタグ名によるキーワード一致（検索ボックスはファイル名／説明のみが対象で、タグ名には一致しない）は現時点で未実装のため対象外とする。
- 文書データは初期状態では0件であり、各テストの前提条件に記載した文書をアップロードしてから検証する。
- ページネーションの実装（MUI DataGrid、`pageSizeOptions={[5, 10, 25]}`、デフォルト10件）は、`spec.md` の FR-010（「1ページあたり20件の文書を表示」）とは件数が乖離している。本仕様書では実装に合わせて `pageSizeOptions` に存在する「5件」表示を用いて検証する。

## 文書一覧にアップロード済みの文書情報が表示されること

### データ

| ファイル名           |
| --------------------- |
| 田中商事_請求書.pdf   |
| 佐藤建設_契約書.pdf   |

### 前提条件

- テスト実行前に上記2件の文書がアップロードされていること

### 手順

1. 文書一覧ページ（`/`）にアクセスする
2. 「マイファイル」の一覧に「田中商事_請求書.pdf」の行が表示されること
3. 同じ行に更新日時（Last Modified 列）が表示されること
4. 同じ行にファイルサイズ（File Size 列）が表示されること
5. 「佐藤建設_契約書.pdf」についても同様に一覧へ表示されること

### 事後処理

- ページをリロードし、MSW（Mock Service Worker）がインメモリで保持しているモックファイルデータをリセットする（他のテストへの影響を防ぐため）

## ファイル名列ヘッダーをクリックすると昇順にソートされること

### データ

| ファイル名                                                        |
| ------------------------------------------------------------------ |
| 田中商事_請求書.pdf、佐藤建設_契約書.pdf、資料001.pdf〜資料003.pdf（合計5件） |

### 前提条件

- テスト実行前に上記5件の文書がアップロードされていること

### 手順

1. 文書一覧ページ（`/`）にアクセスする
2. 「Rows per page:」のセレクトボックスで「5」を選択する
3. 「Name」列ヘッダーをクリックする
4. 1ページ目（5件表示）の並び順が「佐藤建設_契約書.pdf」→「資料001.pdf」〜「資料003.pdf」→「田中商事_請求書.pdf」の順になること

### 補足

- 一覧の並び替えはページネーション（`paginationMode="server"`）とは独立に、
  現在フェッチ済みの行（現在のページの行）に対してのみクライアント側で行われる
  （MUI DataGrid の `sortingMode` はデフォルトの `client` のまま）。
  そのため、このテストでは総件数をページサイズ（5件）と一致させ、
  1回のフェッチで全件が読み込まれた状態でソートを検証する。

### 事後処理

- ページをリロードし、MSWがインメモリで保持しているモックファイルデータをリセットする

## ページネーションで次のページ・前のページに移動できること

### データ

| ファイル名                                                        |
| ------------------------------------------------------------------ |
| 田中商事_請求書.pdf、佐藤建設_契約書.pdf、資料001.pdf〜資料005.pdf（合計7件） |

### 前提条件

- テスト実行前に上記7件の文書が「田中商事_請求書.pdf → 佐藤建設_契約書.pdf → 資料001.pdf → 資料002.pdf → 資料003.pdf → 資料004.pdf → 資料005.pdf」の順にアップロードされていること

### 手順

1. 文書一覧ページ（`/`）にアクセスする
2. 「Rows per page:」のセレクトボックスで「5」を選択する
3. ページ下部に「1–5 of 7」と表示され、1ページ目に5件の文書が表示されていること
4. 「Go to next page」ボタンをクリックする
5. 2ページ目に残り2件の文書が表示され、「6–7 of 7」と表示されること
6. 「Go to next page」ボタンが無効化されていること
7. 「Go to previous page」ボタンをクリックすると1ページ目（5件表示、「1–5 of 7」）に戻ること

### 事後処理

- ページをリロードし、MSWがインメモリで保持しているモックファイルデータをリセットする

## キーワード検索でファイル名が一致する文書のみ表示されること

### データ

| ファイル名           | 検索キーワード |
| --------------------- | -------------- |
| 田中商事_請求書.pdf   | 田中商事       |
| 佐藤建設_契約書.pdf   |                |

### 前提条件

- テスト実行前に上記2件の文書がアップロードされていること

### 手順

1. 文書一覧ページ（`/`）にアクセスする
2. 検索ボックスに「田中商事」と入力する
3. 300ms のデバウンス処理が完了するまで待機する（検索は入力から300ms後に実行される）
4. 一覧に「田中商事_請求書.pdf」のみが表示されること
5. 「佐藤建設_契約書.pdf」が一覧に表示されないこと

### 事後処理

- ページをリロードし、MSWがインメモリで保持しているモックファイルデータをリセットする

## 検索バーをクリアするとすべての文書が再表示されること

### データ

| ファイル名           | 検索キーワード |
| --------------------- | -------------- |
| 田中商事_請求書.pdf   | 田中商事       |
| 佐藤建設_契約書.pdf   |                |

### 前提条件

- テスト実行前に上記2件の文書がアップロードされていること
- 検索ボックスに「田中商事」と入力し、300ms のデバウンス処理完了後に検索結果が「田中商事_請求書.pdf」のみに絞り込まれていること

### 手順

1. 検索ボックス右側のクリアボタン（×）をクリックする
2. 検索ボックスが空になること
3. 一覧に「田中商事_請求書.pdf」と「佐藤建設_契約書.pdf」の両方が再表示されること

### 事後処理

- ページをリロードし、MSWがインメモリで保持しているモックファイルデータをリセットする

## 該当する文書が見つからない場合にメッセージが表示されること

### データ

| 検索キーワード           |
| ------------------------ |
| 存在しないキーワードXYZ  |

### 前提条件

- テスト実行前に文書が1件以上アップロードされていること

### 手順

1. 文書一覧ページ（`/`）にアクセスする
2. 検索ボックスに「存在しないキーワードXYZ」と入力する
3. 300ms のデバウンス処理が完了するまで待機する
4. `data-testid="emptySearchResult"` の要素が表示されること
   - 表示文言（例:「検索結果が見つかりませんでした」）は i18n 設定により変わりうるため、テキスト一致ではなく `data-testid="emptySearchResult"` の表示有無で判定すること

### 事後処理

- ページをリロードし、MSWがインメモリで保持しているモックファイルデータをリセットする
