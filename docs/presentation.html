独自実装：ダークテーマ ＋ コマンドパレット

Raycast 型のオーバーレイ。既存レイアウトに手を入れずに機能だけを足す

1
ダークテーマ + 切替

MUI のテーマを二重定義し、ヘッダーのボタンで切替。選択は localStorage に保存され、リロード後も維持される。既存の言語切替と同じ構造で実装した。

2
コマンドパレット（⌘K）

どの画面からでも文書を検索。↑↓ で移動、Enter で詳細、Esc で閉じる。既存の useFiles を流用し、新規 API は追加していない。

なぜ「重ねる」形にしたのか

画面レイアウトを作り替える案もあったが、それだと Day 3 で書いた E2E テストを作り直すことになる。オーバーレイなら既存の DOM 構造が変わらないため、テスト 12 件を一切触らずに機能を追加できた。

→ 結果：既存 12 件 ＋ 新規 3 件 ＝ 15 件すべてパス

実物を触らないと分からなかったこと

Playwright MCP で画面を操作して初めて判明。仕様書には書かれていない

1
資料の URL /files は存在せず、実際は / だった
信じて書いていたら全テストが落ちていた
2
検索に 300ms のデバウンスがあった
知らずに書くと「時々落ちる」テストになる
3
ソートは client、ページングは server
並び替えが 1 ページ目にしか効かない、実装上の不整合
4
GET /files を「最近使用したファイル」も叩いていた
レスポンス待ちでは特定できず、待ち方の設計をやり直した
5
MUI が付ける data-testid は本番ビルドで消える
ライブラリのソースを読んで判明。自前の目印を追加した

AI は「調べる・書く・直す」が速い。人は「何を良しとするか」を決める。

テスト範囲を絞る判断、生成物のレビュー、環境問題とコード問題の切り分けは自分の仕事だった。
